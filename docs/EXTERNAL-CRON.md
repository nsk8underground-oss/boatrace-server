# 外部cronサービスから自動投稿を動かす手順

## なぜ必要か

GitHub Actions の定期実行（cron）は、このリポジトリでほぼ機能していません。

実測（2026/09/07〜09/10）:

| 設定 | 期待 | 実際 |
|---|---|---|
| `0,30 1-11 * * *`（1日22回） | 22回/日 | **1〜3回/日** |
| 起動時刻 | 指定どおり | **数十分〜4時間遅れ**、指定時刻外にも起動 |

GitHub のドキュメントにも「混雑時は遅延またはスキップされる」と明記されており、無料枠では時刻の保証がありません。予想の投稿は「締切15〜90分前」という時間の制約があるため、この不安定さは致命的です。

外部の cron サービスから直接エンドポイントを叩けば、指定時刻どおりに実行されます。

---

## 使うもの

**cron-job.org**（無料・登録のみ・クレジットカード不要）
https://cron-job.org/

他のサービス（EasyCron, UptimeRobot など）でも同じ考え方で設定できます。

---

## 1. 呼び出すURL

```
https://veryboatrace-server-sq9y.vercel.app/api/auto-post?mode=races
```

```
https://veryboatrace-server-sq9y.vercel.app/api/auto-post?mode=results
```

このエンドポイントは `CRON_SECRET` で保護されており、**サイトのパスワード（Basic認証）は不要**です。

---

## 2. 合言葉の渡し方

**推奨: リクエストヘッダ**

cron-job.org のジョブ設定 → **Advanced** → **Headers** に追加:

| Key | Value |
|---|---|
| `x-cron-secret` | Vercelに設定した `CRON_SECRET` の値 |

**代替: URLのクエリ**

ヘッダが設定できないサービスの場合は、URLの末尾に付けられます:

```
...?mode=races&secret=<CRON_SECRETの値>
```

⚠️ この方法だと合言葉がURLに残ります（サービスのログや履歴に記録されます）。ヘッダ方式を推奨します。

---

## 3. スケジュール設定

cron-job.org は**タイムゾーンを指定できる**ので、JSTのまま設定できます（UTC換算は不要です）。

**ジョブ①: レース予想**
- Title: `boatrace 予想投稿`
- Schedule: 毎日 **10:00〜20:00**、**30分ごと**
  （Custom で `0,30` 分 / `10-20` 時 を指定）
- Timezone: **Asia/Tokyo**

**ジョブ②: 結果まとめ**
- Title: `boatrace 結果まとめ`
- Schedule: 毎日 **21:30**
- Timezone: **Asia/Tokyo**

---

## 4. 動作確認

保存後、ジョブの **「Run now」**（今すぐ実行）を押してください。

レスポンスに以下のいずれかが返れば成功です:

| レスポンス | 意味 |
|---|---|
| `"posted":{"ok":true,...}` | 投稿成功 |
| `"skipped":"締切15〜90分前のレースなし"` | 正常（対象レースが無い時間帯） |
| `"skipped":"対象レースは投稿済み"` | 正常（重複防止が働いた） |
| `{"error":"invalid cron secret"}` | 合言葉が違う → ヘッダ/クエリの値を確認 |

---

## 補足

- **投稿数は増えません。** 何回叩かれても、同一レースの重複投稿は防止され、1日の上限（8件）も維持されます
- **GitHub Actions のワークフローはそのまま残してあります。** 手動実行（Run workflow）でのテストに使えますし、たまに起動したときの予備にもなります
- 合言葉を変更したい場合は、Vercelの `CRON_SECRET` と cron-job.org 側の両方を同じ値に更新してください
