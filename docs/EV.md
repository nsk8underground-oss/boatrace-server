# 買い目の決め方と、確率の校正

このBOTは「人気だから買う」ことをしません。人気順に買うと、控除率25%のぶんだけ
回収率が必ず100%を下回るためです。代わりに次の順序で決めます。

1. AIには**オッズを見せずに**、各3連単の的中確率を見積もらせる
2. サーバーが実オッズを取ってきて、期待値 = 確率 × オッズ を計算する
3. 期待値が基準を超えた組だけを買う。1点も無ければ**見送り**

## AIの確率はそのままでは使えない

70レース・候補412点ぶんの実測（`/api/calibration`）でこうなりました。

| AIが言った確率 | 候補数 | 実際に当たった率 |
|---|---|---|
| 1〜2% | 95 | 3.16% |
| 2〜5% | 149 | 2.68% |
| 5〜10% | 107 | 3.74% |
| 10〜20% | 53 | 3.77% |

**AIが確率を高く付けた組ほど当たる、という関係がほとんど見えません。**
本命級（10〜20%と言った組）の実績は3.8%で、3〜4倍の過大評価です。
ブライアスコアもAI 0.2805 に対し市場 0.1845 で、市場の確率のほうが正確でした。

この生の確率で期待値を出すと、**どのレースも期待値1.0超えに見えてしまいます**。
実際に70レースすべてで6点ずつ買い、見送りは一度も出ず、回収率は80%でした。
控除率をそのまま被っていたということです。

## 市場に寄せて校正する

各組で、AIの確率と市場の確率の幾何平均を取ります。

```
g(組) = AIの確率^w × 市場の確率^(1-w)      w = EV_AI_WEIGHT（既定 0.4）
校正後の確率 = g(組) / Σg × （候補全体の市場確率の合計）
```

市場の確率はオッズの逆数を正規化したもの（`marketImplied`）で、全120組のオッズが
そろっているときだけ求めます。求められないレースは期待値を名乗りません（`ev_mode=nomarket`）。

合計を市場の合計に合わせているのが要点です。こうすると期待値は

```
期待値(組) ≒ (1 - 控除率) × （AIと市場の食い違いの大きさ）
```

だけで決まります。**AIが確率を一律に盛っても買い目の判定は動きません。**
AIが市場と大きく食い違う組だけが残り、食い違いが無いレースは見送りになります。

## 重み w をどう置いているか

実測を素直に読めば `w = 0`、つまり市場の確率をそのまま使う＝常に見送りが正解です。
ただし的中はまだ13件しかなく、傾きの推定はぶれます。
そこで「AIが市場と大きく食い違う組だけを少量買って測り続ける」ために **0.4** に置いています。

- 環境変数 `EV_AI_WEIGHT` で 0〜1 に変えられます（Vercel の Environment Variables）
- 1にすると校正前の挙動（AIの見立てをそのまま使う）に戻ります
- 下げるほど見送りが増えます

**この重みは「AIに勝ち目がある」と示すものではありません。** 現時点で勝ち目は
測れていません。測りながら損を小さく保つための設定です。

## 買う基準

| 定数 | 値 | 意味 |
|---|---|---|
| `EV_MIN_MAIN` | 1.05 | 本線に採用する最低期待値 |
| `EV_MIN_ANA` | 1.20 | 穴は当たりが薄くブレるので高めに要求する |
| `ANA_MIN_ODDS` | 30 | これ以上を穴として扱う |
| `EV_MIN_P` | 0.5% | 校正後の確率がこれ未満の組は買わない |
| `MAX_MAIN` / `MAX_ANA` | 4 / 2 | 合計6点（¥600）まで |

`EV_MIN_P` は、市場に寄せると期待値を満たす組が人気薄に偏るためです。
確率0.3%の組を当てる見積もりは誤差のほうが大きく、3倍外していても分かりません。
見積もりの解像度が足りない領域には踏み込まない、という下限です。

## 効き方（実際の投稿）

校正を入れると点数が減り、的中率の表示も正直な数字に下がります。

```
🚤平和島 1R 締切16:01 計5点¥500

◎本線 的中率4.7% 期待値1.15
4-3-1　4-1-5　1-4-6　4-2-3

★穴 的中率0.8% 期待値1.24
4-1-6
```

的中率4.7%は「20回に1回しか当たらない」という意味です。期待値1.15が本当なら
長い目では増えますが、**ぶれは非常に大きい**ので、そのつもりで見てください。

食い違いが無いレースはこうなります。

```
🚤平和島 4R 締切16:01

⚠️見送り
市場の評価と見立てが食い違う組がなく、期待値1.0を超える買い目がありません
```

## 測り方

```
https://<あなたのドメイン>/api/calibration
```

| 項目 | 見かた |
|---|---|
| `calibrated` | **まず見るのはここ。** 校正を入れたあとの記録だけの成績 |
| `modes` | `ev` 以外が混じっていたら、そのレースは期待値で選べていない |
| `byDay` | 日別。`cal` が校正の有無。校正を入れた日から `skipped` が増えるはず |
| `skipped` | 見送りの数。0のままなら判定が効いていない |
| `calibration` | 買い目を決めるのに使った確率（校正後）の当たり具合 |
| `calibrationRaw` | AIの生の見積もりの当たり具合。AI自体が上手くなったかはここで見る |
| `brier` | AIと市場、どちらの確率が正確か |

`calibration` と `brier` は、校正後（`w` 付き）の記録があればそれだけを対象にします。
**同じ `mode=ev` でも、校正を入れる前は水増しされた確率で6点選んでいる**ので、
混ぜるとどちらの成績も読めなくなります（`noodds` が混ざっていたときと同じ失敗）。

### 1レースずつ見る

```
/api/calibration?detail=1&days=3
```

回収率やバケットの平均では「どの予想がどう外れたか」が見えません。
`detail=1` は1レースずつ、買った組・着順・配当と、確率の内訳を返します。

| 項目 | 意味 |
|---|---|
| `bought` | 実際に買った組。`[]` は見送り |
| `betP` / `betMktP` | 買った組の合計確率（校正後）と、同じ組に市場が置いていた確率 |
| `aiP` / `aiPRaw` / `mktP` | 勝った組に、校正後・AIの生・市場がそれぞれ置いていた確率 |

`betP` が `betMktP` より大きいほど「市場より当たりやすいと見て買った」ということです。
その差が当たりにつながっていないなら、見立てに価値が無いということになります。

`calibration` の `predicted` と `actual` が近いほど、確率の見積もりが正確です。
`roi` は100レースぶん貯まるまで大きくぶれるので、少ない件数で判断しないでください。

見送ったレースも材料を残しているので（投稿上限に達して投稿しなかった分も含む）、
「買わなかった判断が正しかったか」も測れます。
