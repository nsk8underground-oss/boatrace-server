# 潮位の自動取得

平和島や江戸川のような汽水の水面では、潮の高さと流れがターンの決まり方を変えます。
boatrace.jp は潮位を出さないので、**気象庁の潮位表（推算値）** を読んでAIに渡しています。

## データの出どころ

```
https://www.data.jma.go.jp/kaiyou/data/db/tide/suisan/txt/<年>/<地点記号>.txt
```

1地点1年ぶんが1ファイル、1行が1日の固定長テキストです。

| 桁 | 内容 |
|---|---|
| 1–72 | 毎時潮位（3桁 × 24時間、cm） |
| 73–78 | 年月日（YYMMDD） |
| 79–80 | 地点記号 |
| 81–108 | 満潮（時刻4桁 + 潮位3桁）× 4組 |
| 109–136 | 干潮（同上）× 4組 |

欠測は時刻が `9999`、潮位が `999` です。

年ファイルは1年間変わらないので、取得したテキストはサーバー内に12時間、
日ごとに切り出したデータは Redis に7日間キャッシュします。
1日あたりの取得は1回だけです。

## AIに渡している内容

締切時刻の潮位を毎時値から補間し、そのとき潮が上げているか下げているかを添えます。

```
潮位:締切時点142cm（下げ潮・干潮18:30まで360分） 本日 満潮08:20(186cm) 干潮18:30(86cm)（気象庁の推算値）
```

転流の前後30分は向きを断定せず「満潮前後」「干潮前後」とだけ書きます。

## 場と地点の対応

| 場コード | 場 | 気象庁の地点記号 |
|---|---|---|
| 03 | 江戸川 | TK（東京） |
| 04 | 平和島 | TK（東京） |

**この対応が正しいかは、実際に動かして確認してください。** 地点記号を取り違えると、
別の場所の潮位が何事もなく表示されてしまいます。確認は次の1手です。

```
https://<あなたのドメイン>/api/tide?jcd=04&hd=20260918
```

返ってくる `highs` / `lows` の時刻と潮位を、気象庁の潮位表
（https://www.data.jma.go.jp/kaiyou/db/tide/tide_table/ の「東京」）と見比べてください。
`source` に実際に読んだURLも入っています。`&debug=1` を付けると毎時潮位も返します。

## 他の場を追加する / 地点を変える

環境変数 `TIDE_STATIONS` に JSON で指定します（Vercel の Environment Variables）。

```
TIDE_STATIONS={"22":"HD","24":"OM"}
```

- キーは場コード（2桁）、値は気象庁の地点記号（2文字）
- 値を空文字にすると、その場の潮位取得を止められます: `{"03":""}`
- 追加したら必ず `/api/tide?jcd=<場コード>&hd=<日付>` で値を確かめてください

潮位が取れない場・取れない日は、潮位の行がプロンプトから抜けるだけで、
予想そのものは今までどおり出ます。
